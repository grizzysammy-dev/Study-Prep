# iptables

The Linux kernel firewall: it inspects packets at fixed points (chains) and decides ACCEPT / DROP / rewrite. Picture every packet walking a corridor with inspection desks at fixed doorways — *just arrived*, *about to be routed*, *destined for us*, *on its way out* — and at each desk a guard runs top-to-bottom down a checklist, takes the action of the **first** line that matches, and stops. That's the whole machine: checklists (rules) bolted to doorways (chains), running inside the kernel before your services ever see the traffic. This is a **heavily-tested JQR project** (Module 1) — you must build a safe default-deny host firewall, NAT between subnets, and make the rules survive a reboot on **both** Debian/Ubuntu and CentOS. Learn the build *order* until it's muscle memory.

## TL;DR
```bash
# safe host firewall — allow FIRST, DROP policy LAST (never lock yourself out)
sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT        # SSH — add BEFORE the drop
sudo iptables -P INPUT DROP                               # flip the policy LAST
sudo iptables -L -n -v --line-numbers                     # read the ruleset (with counters)
sudo iptables -t nat -A POSTROUTING -s 10.10.10.0/24 -o ens33 -j MASQUERADE   # SNAT out
sudo iptables-save > /etc/iptables/rules.v4              # persist Debian/Ubuntu
sudo service iptables save                               # persist CentOS (/etc/sysconfig/iptables)
```

## Concept
### Tables — *what kind* of processing
| Table | Used for |
|---|---|
| `filter` | **default** — allow/deny (INPUT, OUTPUT, FORWARD) |
| `nat` | rewrite address/port (PREROUTING, POSTROUTING, OUTPUT) — masquerade, port-forward |
| `mangle` | alter fields (TTL, TOS, marking) — advanced |
| `raw` | conntrack exemptions — rarely needed |

### Chains — *where in the packet's journey* rules run
| Chain | Fires on... |
|---|---|
| `INPUT` | packets **destined for this host** |
| `OUTPUT` | packets **generated by this host** |
| `FORWARD` | packets **passing through** (routed) — needs `ip_forward=1`, see [Interfaces IPs and Routing](../Linux%20Admin/Interfaces%20IPs%20and%20Routing.md) |
| `PREROUTING` | as packets **arrive**, before the routing decision (DNAT) |
| `POSTROUTING` | just **before packets leave**, after routing (SNAT/MASQUERADE) |

### The four ideas that matter
- **Order:** top-to-bottom, **first match wins**. The first matching rule decides the packet and processing stops — put specific ACCEPTs **above** broad DROPs.
- **Policy (`-P`):** fate of a packet matching **no** rule in a built-in chain. *Whitelist (secure)* = policy DROP + explicit ACCEPTs; *blacklist (loose)* = policy ACCEPT + specific DROPs.
- **Stateful filtering (conntrack):** `NEW` / `ESTABLISHED` / `RELATED` / `INVALID`. One rule — allow `ESTABLISHED,RELATED` — lets replies back in without writing a matching OUTPUT rule for every service. This is the single most important idea for a clean ruleset.
- **DROP vs REJECT:** DROP is silent (attacker sees a timeout); REJECT politely replies "closed" (reveals a host is there). **DROP is the stealthier default** for a hardened host.

### Command grammar
```text
iptables -A <CHAIN> [match conditions] -j <TARGET>
  -A append  -I insert(top)  -D delete  -L list  -S dump-rules  -F flush  -P policy
  -p tcp|udp|icmp   --dport N   -s SRC   -d DST   -i IN_IF   -o OUT_IF
  -m conntrack --ctstate NEW,ESTABLISHED,RELATED,INVALID
  -j ACCEPT|DROP|REJECT|LOG|SNAT|DNAT|MASQUERADE|REDIRECT
  -t nat|mangle          # default table is filter
```

## Build a host firewall IN THE RIGHT ORDER
> [!danger] The #1 mistake: `-P INPUT DROP` **before** the SSH allow rule. On a remote box that **instantly kills your session** and locks you out. Always allow **loopback + established + SSH FIRST**, and flip the policy to DROP **LAST**.

> 🧪 **Run this on your lab** — verified against current docs, confirm on your box. (Live firewall rules need root; do it on a VM you can console into.)

```bash
sudo iptables -F                                                   # 1. start clean
sudo iptables -A INPUT -i lo -j ACCEPT                             # 2. loopback must always work
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT   # 3. keep return traffic (incl. your SSH)
sudo iptables -A INPUT -m conntrack --ctstate INVALID -j DROP      # 4. bin obviously broken packets
sudo iptables -A INPUT -p tcp --dport 22  -j ACCEPT               # 5. SSH  (BEFORE the drop policy!)
sudo iptables -A INPUT -p tcp --dport 80  -j ACCEPT               #    HTTP
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT               #    HTTPS
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT #    ping
sudo iptables -A INPUT -j LOG --log-prefix "iptables-DROP: " --log-level 4   # 6. log the leftovers
sudo iptables -P INPUT DROP                                        # 7. ONLY NOW deny everything else
sudo iptables -P FORWARD DROP                                      #    not a router? deny transit
sudo iptables -P OUTPUT ACCEPT                                     #    usually let our box talk out
```
→ Safety net before flipping to DROP on a box you could lose: `sudo sh -c 'sleep 300 && iptables -F' &` auto-flushes in 5 min if you strand yourself.

> ✅ **Tested output** (Ubuntu 24.04, 2026): the same allow-SSH/HTTP/HTTPS/ICMP + established, then log-and-drop logic, built into a custom chain `LABDEMO` and dumped with `iptables -S`:
```
$ iptables -S LABDEMO
-N LABDEMO
-A LABDEMO -i lo -j ACCEPT
-A LABDEMO -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
-A LABDEMO -p tcp -m tcp --dport 22 -j ACCEPT
-A LABDEMO -p tcp -m tcp --dport 80 -j ACCEPT
-A LABDEMO -p tcp -m tcp --dport 443 -j ACCEPT
-A LABDEMO -p icmp -j ACCEPT
-A LABDEMO -j LOG --log-prefix "DROP-LAB: "
-A LABDEMO -j DROP
```
→ `-S` prints rules **as the `iptables -A …` commands that recreate them** — the fastest way to screenshot/verify your build. Note the order is exactly the sequence above: loopback → established → service ports → LOG → DROP.

### "Block all traffic except SSH" — exact minimal set
The classic JQR one-liner set; order preserved so you never lose the session.
```bash
sudo iptables -F
sudo iptables -A INPUT -i lo -j ACCEPT                                        # loopback
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT   # return traffic
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT                            # SSH in
sudo iptables -P INPUT DROP                                                   # everything else denied
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT
```
→ Only inbound SSH (plus replies to connections we started) survives; all other inbound is dropped silently. Verify: `sudo iptables -L -n -v --line-numbers`.

## NAT — MASQUERADE & SNAT (rewrite the source, on the way OUT)
Scenario: the box is a router/pivot. Hosts on `10.10.10.0/24` (behind `ens34`) need to reach the primary LAN/internet through `ens33`. Their private source must be **rewritten** to the box's `ens33` address or replies have nowhere to return. Source NAT lives in **POSTROUTING** (last stop before the packet leaves).
Prereq: `net.ipv4.ip_forward=1` (see [Interfaces IPs and Routing](../Linux%20Admin/Interfaces%20IPs%20and%20Routing.md)) **and** a FORWARD allow.

> **Why it works:** the box records every rewrite in its conntrack table, so when a reply lands on *its* address it knows which private host to hand it back to — and rewrites the destination back before forwarding it inward. NAT is really "lie about the address on the way out, un-lie on the way back," and conntrack is the memory that makes the un-lying possible. **DNAT** (below) is the exact same trick aimed the other way: rewrite the *destination* on the way in. *This is also why NAT is a headache on the blue side — the collector sees the router's address, not the real internal host, unless you log the translation.*

**MASQUERADE** — outgoing IP is **dynamic** (DHCP): auto-detects the interface's current address.
```bash
sudo iptables -t nat -A POSTROUTING -s 10.10.10.0/24 -o ens33 -j MASQUERADE
sudo iptables -A FORWARD -i ens34 -o ens33 -j ACCEPT
sudo iptables -A FORWARD -i ens33 -o ens34 -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```
**SNAT** — outgoing IP is **static and known** (slightly faster, no per-packet lookup).
```bash
sudo iptables -t nat -A POSTROUTING -s 10.10.10.0/24 -o ens33 -j SNAT --to-source 192.168.1.50
```
| | **MASQUERADE** | **SNAT** |
|---|---|---|
| Source IP | auto = interface's current IP | you specify it (`--to-source`) |
| Best for | dynamic/DHCP/VPN uplinks | static uplink IP |
| Cost | recomputes per packet | fixed, marginally faster |

## DNAT / REDIRECT — rewrite the destination, on the way IN
Scenario: anything hitting the router's `ens33` address on TCP 8080 should be forwarded to internal host `10.10.10.20:80`. Destination NAT lives in **PREROUTING** (before the routing decision).
```bash
sudo iptables -t nat -A PREROUTING -i ens33 -p tcp --dport 8080 -j DNAT --to-destination 10.10.10.20:80
sudo iptables -A FORWARD -p tcp -d 10.10.10.20 --dport 80 -j ACCEPT   # permit the now-forwarded packet
```
Local **REDIRECT** — bounce a port on *this* host (e.g. 80 → 8080 for a non-root service):
```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
```
> [!warning] NAT gotchas
> - **NAT without forwarding does nothing.** `ip_forward=1` is mandatory for SNAT/DNAT/MASQUERADE between interfaces.
> - **SNAT/MASQUERADE = POSTROUTING (out); DNAT/REDIRECT = PREROUTING (in).** Mixing these up is the most common NAT bug.
> - Keep the **return-path FORWARD rule** (the `ESTABLISHED,RELATED` one) or replies get dropped and you'll see one-way traffic — confirm with [Tcpdump](../Recon%20Tools/Tcpdump.md).

## LOG traffic that isn't allowed (before the drop)
`LOG` is **non-terminating** — the packet keeps walking the chain — so put it **immediately before** the drop/policy to record exactly what's about to be denied.
```bash
sudo iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables-DROP: " --log-level 4
sudo iptables -A INPUT -j DROP
```
→ `--log-prefix` tags each line so you can `grep` it out of the noise (keep it short, ~29-char limit); `--log-level 4` = *warning*; `-m limit` stops a flood filling the disk.

Where the logs land (the **kernel ring buffer**):
```bash
sudo dmesg | grep "iptables-DROP"
sudo journalctl -k | grep "iptables-DROP"      # systemd journal (kernel) — see [Logs and journalctl](../Linux%20Admin/Logs%20and%20journalctl.md)
# Debian/Ubuntu also: /var/log/kern.log   |   CentOS: /var/log/messages
```

## Persist rules across reboot
Live `iptables` rules are **RAM-only** and vanish on reboot — always finish with a save step.

### Debian / Ubuntu — iptables-persistent
```bash
sudo apt update && sudo apt install iptables-persistent   # prompts to save current v4/v6 rules
sudo iptables-save  | sudo tee /etc/iptables/rules.v4     # save v4 manually
sudo ip6tables-save | sudo tee /etc/iptables/rules.v6     # save v6
sudo netfilter-persistent save                            # snapshot live rules -> those files
sudo netfilter-persistent reload                          # reload from files now
```
→ At boot, `netfilter-persistent` runs `iptables-restore < /etc/iptables/rules.v4` automatically. **Debian/Ubuntu file: `/etc/iptables/rules.v4`.**

### CentOS Stream 10 — the iptables service
CentOS ships **firewalld** (nftables backend) by default. For a raw-iptables project, install the iptables service and stop firewalld so they don't fight.
```bash
sudo dnf install -y iptables-nft-services      # older RHEL/CentOS: iptables-services
sudo systemctl disable --now firewalld         # stop firewalld clobbering your rules
sudo systemctl enable --now iptables ip6tables # load rules at boot
sudo service iptables save                      # writes /etc/sysconfig/iptables
# equivalent: sudo sh -c 'iptables-save > /etc/sysconfig/iptables'
```
→ **CentOS file: `/etc/sysconfig/iptables`** (and `/etc/sysconfig/ip6tables`). If the project *allows* firewalld, "allow SSH" is `sudo firewall-cmd --permanent --add-service=ssh && sudo firewall-cmd --reload` — but the JQR asks for **iptables**, so mask firewalld and use the raw rules.

> [!warning] Persistence gotchas
> - Don't cross the files up: **Debian/Ubuntu `/etc/iptables/rules.v4`** vs **CentOS `/etc/sysconfig/iptables`**.
> - Rules you `-A` but never **save** are gone after reboot. Always finish with a save.

## nftables note (2026 reality)
- **nftables (`nft`)** is the modern kernel firewall backend; classic `iptables` is now usually the **`iptables-nft` shim** — you type iptables syntax and it programs nftables underneath. `iptables --version` shows `(nf_tables)`.
- An equivalent exists (`nft add rule inet filter input tcp dport 22 accept`), and firewalld/`nft` are the "native" tools — **but the JQR asks for iptables**, so keep iptables syntax as your primary answer and just *know* the shim exists.
- Check/switch backend: `sudo iptables -V`; `sudo update-alternatives --config iptables` (legacy vs nft — rarely needed).

## Exam tips & gotchas
- **Order = first match wins.** Specific ACCEPTs go **above** broad DROPs, always.
- **DROP-policy lockout** — loopback + established + SSH FIRST, `-P INPUT DROP` LAST; keep a `sleep && iptables -F` safety net.
- **`ESTABLISHED,RELATED` once** saves you from writing an OUTPUT rule per service.
- **NAT needs forwarding.** No `net.ipv4.ip_forward=1` → SNAT/DNAT/MASQUERADE silently do nothing.
- **SNAT/MASQUERADE = POSTROUTING; DNAT/REDIRECT = PREROUTING.**
- **LOG before DROP** (LOG is non-terminating); rate-limit it with `-m limit`.
- **Persistence files differ** (Debian vs CentOS) and live rules die unless saved.
- **`-S` vs `-L`:** `-S` dumps re-runnable rule commands (great for proof); `-L -n -v --line-numbers` is the human-readable audit with packet/byte counters.
- **DROP vs REJECT** — DROP for stealth on a hardened host.
